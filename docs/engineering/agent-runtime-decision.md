# Agent 运行位置决策

状态：运行位置已确认，首个 demo 已启动实现与 Compose 部署，具体状态见 [demo 技术说明](demo.md)。完整共享工作环境仍属后续阶段。

## 已确认方案

首版采用统一的远程 Agent：Android App 负责界面、设备采集、离线查看和本地提醒；远程 Linux 服务负责对话执行、长任务、完整工作环境和声明式技能改进。用户不必在创建对话时选择“本地”或“云端”。手机技术栈仍为 React Native + Expo + TypeScript。

## 部署安排

初期开发版部署在当前开发机器，作为手机连接的自有服务端；rho 服务统一采用 Docker Compose，不部署到 k3s。公网沿用 Caddy → Tailscale → 本机独立端口，绕过 k3s 入口。未来可能迁移到 Mac mini，但尚未决定；具体运行方式与迁移方案届时再议。

## 为什么提出这个调整

用户要求长任务在切换应用、锁屏后继续，需要按需安装工具并通过 SSH 开展开发，同时使用较老的 Android 11 手机。远程执行可以让任务生命周期独立于手机界面和手机联网状态，减少手机上的持续计算及运行环境维护。

Android 官方说明 Doze 会限制后台网络、作业和普通闹钟；前台服务适用于用户可感知的持续任务，但不能据此承诺手机进程、网络始终可用。基于这些限制，我不建议将手机作为这类完整 Agent 长任务的唯一执行端。这是针对 rho 需求的架构判断，不表示 Android 无法执行后台任务。

## 三种方案的取舍

| 方案 | 优点 | 主要代价 | 建议 |
| --- | --- | --- | --- |
| Agent 和工具都在手机 | 直接访问本地信息；不用部署 Agent 服务 | 完整工具环境、耗电与后台连续执行都需要在老手机上解决；模型仍依赖远程服务 | 不作为首选 |
| 统一远程 Agent，手机提供设备能力 | 完整 Linux 工具环境，任务不依赖 App 界面存活，共用环境容易理解 | 需要运行服务端，并设计手机与服务器的数据同步及权限 | 首版采用 |
| 每个对话选择本地或远程 | 可以针对不同任务选择环境 | 两套执行环境、工具差异、恢复和同步逻辑；用户需理解运行位置 | 暂不引入 |

## 职责分配

- 手机：页面与对话展示、付款页面采集、后续可用的手环接口、通知、已同步提醒、离线缓存，以及用户的确认操作。
- Linux 服务：pi Agent 执行、持久化任务和会话、完整工具环境、模块与事项服务、卡片生成、计划管理、声明式 skill 和文档改进。
- 多个对话共用用户的一套持久工作环境，保留各自会话上下文；对相同文件、事项和任务的并发修改需要协调。
- 执行环境需与服务器上的其他服务隔离，不能因支持安装工具就默认拥有宿主机任意权限。
- 服务端保存业务主记录，手机保存可离线查看的副本；这是已确认的数据归属。用户在手机上的确认和反馈须可靠同步，重复发送不能产生重复账目或任务。
- 计划由 Agent 制订和调整，已同步到手机的提醒由本地执行，避免每次到点都要求模型在线。

## 断网、中断与恢复

- 服务器确认接收的长任务独立运行；手机断网或关闭 App 不应取消它。只有手机本地尚未送达的请求，不能显示为服务端已开始。
- 需要手机提供新截图、手环数据或确认的步骤，手机不可达时等待；服务器不能在手机离线时继续获得实时设备信息。
- 手机断网期间可查看缓存并执行已经安排的本地提醒；新请求和反馈待联网后同步。
- 服务端完成任务后持久保存结果，手机可达时通知并同步。服务器完成时间与手机收到通知时间是两件事，推送方式及实际延迟需要在目标设备验证。
- 手机恢复后按任务标识取回进度，不能重新提交整个任务。服务器自身故障时，同样需要恢复记录和检查外部执行状态，尤其不能盲目重放已在远程电脑执行的操作。
- “远程运行”不保证服务器、模型服务或目标电脑永远在线；失败、待输入、等待设备和可恢复中断应有明确状态。

## 参考 Hermes 的范围

Hermes 官方将 skill 用作按需加载的过程知识，将持久记忆用于长期事实与偏好；经验可整理成今后复用的技能。rho 借鉴这种思路，但遵循用户更窄的要求：自我改进只产出声明式 skill 与文档，不自动修改核心代码，也不因此将 pi 更换为 Hermes。

建议的改进过程是：记录反馈 → 总结可复用经验 → 更新相关说明 → 后续任务按需加载 → 根据后续反馈修正。记录修改原因、前后版本并支持回退；触发频率与效果判断待设计。用户明确要求执行任务时的代码生成、安装工具和自定义模块开发，另按对应产品规则处理。

## 待验证与待决定

- 初期开发版部署在当前开发机器；未来可能迁移到 Mac mini，届时再讨论操作系统、运行方式与迁移方案，不预先认定在 macOS 上原生运行。
- pi 的具体项目与集成接口、隔离运行环境、服务端恢复及并发协调。
- Android 11 上的截图采集、本地提醒、通知送达与同步恢复。
- 声明式技能的可写范围、版本与评估机制；记账规则不能被 skill 改写绕过。
- 原先要求本地保留的自定义模块版本，在远程方案中如何保留、同步及支持回退，不能静默取消这一要求。
- 手机凭证输入与服务器保管方式、审计内容和截图存储边界，后续单独设计；本决策尚未实施，不包含任何实际服务器变更。
